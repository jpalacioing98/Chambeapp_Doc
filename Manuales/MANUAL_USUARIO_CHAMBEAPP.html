1. Introducción Profunda a ChambeApp

ChambeApp no es solo una bolsa de trabajo. Es una plataforma de orquestación de trabajo independiente que resuelve tres problemas fundamentales del mercado informal latinoamericano: desconfianza mutua, pagos informales y falta de trazabilidad. Este manual cubre todas las funcionalidades de la versión 1.11.0 con profundidad técnica y operativa.

1.1 Visión de Producto

ChambeApp es una plataforma de orquestación de trabajo independiente que conecta a quienes necesitan un trabajo (Solicitantes) con quienes saben hacerlo (PDS — Prestadores de Servicios), y permite a negocios locales (Merchants) publicar vacantes y servicios. Todo ocurre en un entorno seguro con verificación de identidad, contratos digitales, pagos en monedas virtuales y sistema de reputación.

Problema Tradicional Solución ChambeApp
Desconfianza mutua — El cliente no sabe si el trabajador es confiable; el trabajador no sabe si le pagarán KYC obligatorio por rol + TrustScore dinámico + Contratos digitales con firma legal + Escrow de monedas virtuales
Pagos informales / fantasmas — Efectivo sin rastro, pagos a medias, "mañana te pago" ChambeCoins (escrow de plataforma) + Contratos digitales con firma legal (Ley 527/1999) + Chambas con evidencias fotográficas y GPS
Falta de trazabilidad — No hay registro de qué se hizo, cuándo, ni evidencias Chambas con check-in/out GPS, evidencias fotográficas con timestamp, timeline inmutable, hitos de pago

1.2 Diferenciadores Clave

Pagos Efectivo / Transferencia sin garantía ChambeCoins (escrow plataforma) + Contratos digitales

1.4 Arquitectura Técnica Resumida

ChambeApp está construido sobre una arquitectura de microservicios ligeros con:

  • Backend: Flask (Python 3.12) + SQLAlchemy + PostgreSQL + PostGIS + Redis + MinIO (S3-compatible)
  • Frontend: React 18 + TypeScript + Vite + React Router 7 + Mapbox GL + Socket.IO
  • IA/ML: LightGBM (Lambdarank) + Feature Engineering (22 features) + Thompson Sampling Bandit
  • Infra: Docker Compose (dev) / Kubernetes (prod) + Supervisord + Celery + Flower
  • Observabilidad: Métricas Prometheus/Grafana + Logs estructurados + Tracing distribuido

2.2 Cambio de Rol en Una Cuenta

Un usuario puede tener múltiples roles simultáneos (ej. ser PDS + Solicitante + Merchant simultáneamente). El cambio es instantáneo:

  • Header → Selector de Rol → Cambio instantáneo de vista
  • Menú Lateral → "Cambiar a vista PDS/Solicitante/Merchant"
  • Cada vista mantiene su navegación, estado y datos independientes
  • Los datos se comparten: Wallet, KYC, Chat, Notificaciones, TrustScore
Dato clave
Un email = una cuenta. Puedes tener múltiples roles en la misma cuenta. No necesitas crear cuentas separadas.

3. Onboarding Inteligente por Rol

El onboarding de ChambeApp se adapta dinámicamente al rol elegido, guiando al usuario en 5 pasos máximos para dejarlo listo para operar. Cada rol tiene su camino específico, pero comparten una base común.

Paso 1: Bienvenida + Rol Principal

  • Selección visual con iconos y descripciones de cada rol
  • Pregunta guía: "¿Qué quieres hacer principalmente?"
  • Opciones: Solicitante (quiero contratar) | PDS (quiero ofrecer mis habilidades) | Merchant (tengo un negocio)
  • Se puede cambiar luego desde el Header → Selector de Rol

Paso 2: Perfil Básico (Común a todos)

  • Foto: Cámara/Galería → Recorte automático 1:1 → Subida a MinIO (bucket avatares)
  • Nombre completo + Teléfono (opcional, verificación SMS opcional)
  • Zona de trabajo/ciudad: Autocompletado Google Places + Punto en mapa (drag) + Radio slider
  • Legal: Aceptación Términos y Condiciones + Política de Privacidad (Ley 1581/2012)

Paso 3: Específico por Rol

🔧 PDS (Prestador de Servicios)
  • Oficios CUOC/SENA: Multi-select catálogo nacional (200+ oficios)
  • Habilidades/Competencias: Por oficio (checkbox por competencia CUOC/SENA)
  • Años Experiencia: Slider 0-40+
  • Categorías de Trabajo: Multi-select (13 categorías base)
  • Zona de Cobertura: Radio km (5-50) + Centro en mapa (drag)
  • Disponibilidad Horaria: Grid L-D (Mañana/Tarde/Noche) — 7x3 checkboxes
  • Portafolio Inicial: Subida guiada de 1-3 trabajos previos (opcional)
👤 Solicitante
  • Categorías de Interés: Multi-select (para recomendaciones ML)
  • Presupuesto Típico: Rangos predefinidos (0-50k, 50k-200k, 200k-500k, 500k-1M, 1M+)
  • Urgencia Habitual: Hoy / Esta semana / Flexible
  • Radio de Búsqueda: Slider 1-50 km (default 15 km)

  • Tipo de Negocio: Comercio / Servicio / Restaurante / Eventos / Otros

4. Seguridad Avanzada y Gestión de Identidad

ChambeApp implementa un modelo de seguridad en capas que combina autenticación robusta, gestión de sesiones inteligente, privacidad por diseño y auditoría inmutable. La seguridad no es una capa adicional: está integrada en cada flujo crítico.

4.1 Autenticación Multi-Capa

Capa Mecanismo Configuración
1. Credenciales Email + Contraseña (bcrypt 12 rounds) Mín 8 chars, 1 mayús, 1 num, 1 especial
2. 2FA (TOTP) App Autenticadora (Google Auth, Authy, 1Password) Obligatorio: Staff, Admin, Superadmin
Opcional: Usuario final (recomendado)
3. 2FA (SMS) Código 6 dígitos vía proveedor (Twilio/Vonage) Fallback si no hay app autenticadora
4. Códigos Respaldo 10 códigos 8 chars (un solo uso) Generados al activar 2FA → Descargar PDF
5. Biometría FaceID / TouchID / Huella (mobile) Desbloqueo app + confirmar acciones críticas

Función Detalle

Activar 2FA con App Autenticadora (Recomendado)

  1. Perfil → Seguridad → Autenticación de dos factores → "Activar con App"

  3. Ingresa código de 6 dígitos de la app → Confirmar

7. Gestión Avanzada de Ofertas y Negociación

    18. Filosofía Económica: Monedas Virtuales vs Ledger COP

    ChambeApp opera con dos economías completamente separadas. Entender esta distinción es clave para no confundir "dinero real" con "monedas de plataforma".

    18.1 Dos Economías Separadas

    ConceptoChambeCoins (Monedas Virtuales)Ledger COP (Contable)
    NaturalezaMoneda virtual de plataformaRegistro contable interno
    OrigenCompra con COP real (ChambePay)Actividad en app (chambas, contratos)
    UsoFirmar contratos, publicar anuncios, destacarSolo métricas / certificado
    Retirable❌ No❌ No (solo métrica)
    Transferible❌ No (salvo reembolso idempotente)N/A
    ExpiraciónPromocionales: 30 díasNo expira
    Visible enBilletera → Pestaña "Monedas"Billetera → Pestaña "Finanzas"

    18.2 Por Qué Esta Separación

    ProblemaSolución Dual
    RegulatorioMonedas virtuales ≠ dinero electrónico (no requieren licencia bancaria)
    FiscalLedger COP = métrica actividad, no renta gravable
    OperativoMonedas = motor de plataforma (cobros, incentivos)
    TransparenciaUsuario ve: "Gané 500k COP en chambas" + "Tengo 200 monedas"

    25. Sistema de Confianza: TrustScore, Endosos, Badges

    La confianza no es subjetiva: se mide, calcula y muestra. El TrustScore (0.0-1.0) es la métrica unificada que alimenta rankings, filtros y elegibilidades.

    25.1 TrustScore: Fórmula Matemática (0.0 - 1.0)

    trust_score = (
    0.25 * KYC_Score                    # 0.0 - 1.0
  + 0.25 * Reputation_Score             # rating/5.0
  + 0.20 * Experience_Score             # min(contratos/50, 1.0)
  + 0.15 * Portfolio_Quality_Score      # min(portafolio/10, 1.0)
  + 0.15 * Referral_Score               # min(referidos/5, 1.0)
)

    41. Bandit Thompson: Exploración Inteligente

    Multi-Armed Bandit por categoría de servicio para rotación inteligente y exploración automática de categorías nuevas/poco volúmenes.

    41.1 Algoritmo Thompson Sampling

    # Prior uniforme por categoría
PRIOR_ALPHA = 1  # Successes + 1 (prior uniforme)
PRIOR_BETA = 1   # Failures + 1 (prior uniforme)

# Selección: Sample Beta(α, β) por categoría → elige el máximo
def select_category(categories):
    samples = []
    for cat in categories:
        a = self.alpha.get(cat, self.PRIOR_ALPHA)
        b = self.beta.get(cat, self.PRIOR_BETA)
        samples.append(np.random.beta(a, b))
    return categories[np.argmax(samples)]

# Actualización
def update(category, accepted):
    if category not in self.alpha:
        self.alpha[category] = self.PRIOR_ALPHA
        self.beta[category] = self.PRIOR_BETA
    if accepted:
        self.alpha[category] += 1
    else:
        self.beta[category] += 1
    self._save_state()

# Feature ML
def get_arm_value(self, category: str) -> float:
    a = self.alpha.get(category, self.PRIOR_ALPHA)
    b = self.beta.get(category, self.PRIOR_BETA)
    return a / (a + b)

    41.2 Persistencia

    • Storage: SystemConfig['bandit_state'] = {alpha: {...}, beta: {...}}
    • Inicialización: Prior Beta(1,1) por categoría nueva
    • Uso en Features: bandit_arm_value = α/(α+β) ∈ [0,1]

    44. FAQ Exhaustivo: 55+ Preguntas Resueltas

    Respuestas directas a las dudas más frecuentes, organizadas por categoría.

    💰 Monedas y Pagos (1-10)

    1. ¿Las ChambeCoins se pueden cambiar por dinero real?

    No. Son moneda virtual de uso exclusivo dentro de la plataforma (firmar contratos, publicar anuncios). No son retirables, transferibles a efectivo ni intercambiables entre usuarios.

    2. ¿Cuánto cuestan las monedas?

    Depende del paquete. Ejemplo: Básico 50 monedas = $5.000 COP ($100/moneda), Estándar 165 monedas = $15.000 COP ($91/moneda), Premium 400 monedas = $30.000 COP ($75/moneda). Ver catálogo en Billetera → Paquetes.

    3. ¿Cómo funciona el pago simulado (ChambePay)?

    1. Eliges paquete → Checkout → Se crea PagoSimulado estado pendiente (15 min TTL).
    2. Redirige a /pago/simulado/:id → Fases visuales: Conectando → Verificando → Acreditando.
    3. Auto-confirma (o webhook) → Estado completado → Crea CompraPaquete → Acredita monedas instantáneo.
    4. Toast "Se acreditaron N monedas" + Redirect automático a donde estabas.

    4. ¿Qué pasa si me quedo sin monedas en medio de una acción?

    La app detecta MONEDAS_INSUFICIENTES: → Modal "Te faltan N monedas" → Botón "Recargar ahora" → Te lleva a /comprar-monedas?return_to=... → Tras comprar, vuelve y reintenta automáticamente la acción original.

    5. ¿Cuántas monedas cuesta firmar un contrato?

    Fórmula: max(10, trunc((monto × 3%) / 100) + 1) monedas por cada parte.
    Ejemplos: $50k → 10 monedas | $100k → 31 | $500k → 151 | $1M → 301. Configurable por Superadmin (pct_contrato, precio_moneda_cop, monedas_fijas, min_monedas_contrato).

    6. ¿Cuánto cuesta publicar un anuncio?

    10 monedas (publicar) / 5 monedas (reactivar). Configurable por Superadmin (costo_publicar_anuncio, costo_reactivar_anuncio).

    7. ¿Puedo transferir monedas a otro usuario?

    No. Las monedas son intransferibles entre usuarios. Solo se mueven: Usuario ↔ Plataforma (compra, gasto, reembolso, ganancia).

    8. ¿Las monedas expiran?

    Solo las promocionales (bonos, bienvenida, referidos) expiran a los 30 días. Las compradas y ganadas (fidelidad) no expiran nunca.

    10. ¿Qué es el saldo COP en la billetera?

    Es un ledger contable interno (métricas). Registra ingresos/egresos de tu actividad en la app (chambas, contratos, comisiones). No es dinero real, no se retira, no se usa para pagar. Sirve para certificado de ingresos y métricas.

    📝 Solicitudes y Contratos (11-20)

    11. ¿Puedo editar una solicitud ya publicada?

    Sí, mientras esté en estado PUBLICADO y no tenga ofertas aceptadas. Ve a "Mis Solicitudes" → Editar. Si ya hay oferta aceptada, no se puede editar (solo cancelar).

    12. ¿Qué pasa si el PDS no hace check-in/check-out?

    Sin check-in: no hay inicio_en → chamba no inicia formalmente. Sin check-out: no hay fin_en → chamba queda en EN_EJECUCION indefinido. Contacta Soporte si hay disputa.

    13. ¿Puedo cancelar un contrato ya firmado?

    Solo si no ha iniciado (EN_PROGRESO sin check-in). Si ya hubo check-in, debes llegar a acuerdo con la otra parte o abrir disputa.

    14. ¿Qué pasa si el trabajo sale mal / hay disputa?

    Abre Disputa desde Contrato/Chamba/Chat → Formulario (Tipo + Descripción + Evidencias) → Staff asignado → Chat tripartito → Decisión vinculante → Ejecución automática (reembolso monedas, penalización TrustScore, bloqueo).

    Sin check-out 48h → Staff puede force-complete con evidencias. Penalización: -0.15 TrustScore, 7 días bloqueo, -50 monedas. Solicitante puede abrir disputa por abandono.

    48. ¿Qué es el "Bandit" que aparece en la explicación?

    Thompson Sampling por categoría. Aprende qué categorías tienen más éxito. bandit_arm_value = probabilidad estimada de éxito en esa categoría. Ayuda a explorar categorías nuevas.

    49. ¿Cómo sé si estoy en Shadow Mode o ML real?

    En recomendación verás ab_group: "A" = Shadow (heurístico), "B" = ML real (cuando shadow_mode=false). Staff ve en logs: model: "HybridRecommender" | "ShadowRecommender" | "HeuristicRecommender".

    50. ¿Puedo entrenar el modelo con mis datos?

    No directamente. El modelo se entrena offline con datos históricos anonimizados (python -m app.ai.train). Requiere ≥5k samples históricos con positivos/negativos. Superadmin gestiona reentrenamiento.

    Términos de Machine Learning

    TérminoDefinición
    LambdarankAlgoritmo Learning-to-Rank de LightGBM que optimiza NDCG directamente usando gradientes lambda.
    NDCGNormalized Discounted Cumulative Gain. Métrica de ranking que penaliza elementos relevantes en posiciones bajas.
    Learning-to-Rank (LTR)Paradigma ML donde el objetivo es ordenar items, no clasificar/regresar individualmente.
    Groups/Queries (LTR)En Lambdarank, cada "query" (solicitud) define un grupo de candidates. El modelo aprende a rankear dentro de cada grupo.
    Feature ExtractionProceso de transformar datos crudos (usuario, solicitud, contexto) en vector numérico de 22 features normalizadas.
    Retrieval (Two-Stage)Primera etapa: filtrar candidatos masivos (ej. geo) → pocos candidatos. Segunda etapa: rankear con modelo costoso (ML).
    Lambdarank ObjectiveFunción de pérdida que aproxima el gradiente de NDCG. objective='lambdarank' en LightGBM.
    Sigmoid Normalization1 / (1 + exp(-raw_score)) para mapear scores raw de LightGBM a probabilidad [0,1].
    Feature Importance (Gain)Importancia de feature medida por reducción total de pérdida (gain) que aporta en los splits del árbol.
    Cold Start ProblemProblema de recomendar items/usuarios nuevos sin historial. VectorRecommender lo resuelve con embeddings semánticos.
    Online LearningActualización incremental del modelo con nuevos datos sin reentrenar desde cero (partial_fit).
    Partial FitEntrenamiento incremental en LightGBM/XGBoost añadiendo árboles al ensemble existente.
    Thompson SamplingAlgoritmo de bandit que muestrea de distribuciones Beta posteriores para balancear exploración/explotación.
    Multi-Armed Bandit (MAB)Problema de decisión secuencial: elegir entre K opciones (brazos) maximizando recompensa acumulada.
    Prior Beta(1,1)Distribución a priori uniforme para probabilidad de éxito en Thompson Sampling.
    Posterior Beta(α, β)Distribución actualizada tras observar α-1 éxitos y β-1 fallos.
    UCB / Arm ValueUpper Confidence Bound / Valor del brazo. En Thompson: α/(α+β) = media posterior.
    Shadow ModePatrón de deployment: modelo nuevo corre en paralelo, loggea predicciones, pero no afecta usuarios.
    A/B TestingExperimento controlado: grupo A ve versión A, grupo B ve versión B. Métricas comparadas offline/online.
    NDCG@KNormalized Discounted Cumulative Gain at K. Métrica estándar de ranking (1 = ranking perfecto).
    Precision@KProporción de items relevantes en top-K posiciones.
    Rank Correlation (Spearman)Correlación entre dos rankings (ej. ML vs heurístico).
    Divergence RatePorcentaje de queries donde top-1 del modelo A ≠ top-1 del modelo B.
    CalibrationAlineación entre score predicho y probabilidad empírica real (score 0.8 ≈ 80% éxito real).
    Feature EngineeringProceso de crear/transformar features crudas en señales predictivas (normalización, encoding, interacciones).
    Cold StartUsuario/item nuevo sin historial → sin features de historial. Solución: features geográficas + categóricas + bandit.
    Retrieval vs RankingRetrieval = filtrado rápido (millones → cientos). Ranking = ordenación precisa (cientos → top-10).
    PostGIS ST_DWithinFunción geoespacial: ST_DWithin(geom1, geom2, distance_meters) → true si distancia ≤ umbral.
    Haversine FormulaCálculo distancia esférica entre dos puntos lat/lng. Usado cuando no hay PostGIS.
    Sigmoidσ(x) = 1/(1+e⁻ˣ) mapea ℝ → (0,1). Usado para normalizar scores LightGBM a probabilidad.
    JoblibSerialización eficiente de objetos Python (modelos ML, numpy arrays). Mejor que pickle para arrays grandes.
    Joblib Dump/Loadjoblib.dump(obj, path) / joblib.load(path) para persistir modelos LightGBM.
